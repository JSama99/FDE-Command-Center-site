FDE Command Center is an investigation assistant for forward-deployed engineers. It explains why a business system misses its outcomes while the technical system looks healthy. It separates what people say from what the records show, makes you lock a prediction before you look, and calls nothing fixed until a retest proves it.

      Mission Control · five workspaces
      
One case, from brief to engineering record.

      
Mission Control gathers the investigation into five workspaces. The field mission inside it walks ten stages in order, and later stages stay locked until the earlier ones produce their record.

      Durable records
      
    A mission survives a restart. A receipt links only when it can be proven.
    
      
    Every accepted change to a mission is saved as a numbered snapshot, so stopping the server loses nothing. A synthetic investigation receipt attaches to a mission run only through an explicit, checkable link, and every check is recomputed from the stored records. A matching ID proves nothing on its own.
    
    
    
    
    
      
    
        Snapshot revisions · run 
        
      
        
      Each accepted change writes revision N+1, then moves the active-run pointer. The pointer move is the commit point. If a save fails, the previous state stands: reads continue and changes are refused until a restart reconciles.
      
        Link lifecycle · append-only
        
      
          active→
          supersededor
          revoked
        
      
        
      A newer link supersedes the old one, and an operator can revoke one. Records are never edited or deleted.

      Where the AI stops
      
      The model proposes. Rules compute. A person decides.
      
      
      The live model is useful for reading messy evidence and laying out competing explanations. It never writes a fact, a metric, or a verdict, and a response that matches the schema is still checked claim by claim after it arrives.
      
    
      
    
      
      
      
        The model may
        
      Draft and suggest
      
        
        
          
      • Separate policy, stakeholder reports, and recorded events into a truth map
        • 
          
      • Propose at least two competing hypotheses, each with a test that could tell them apart
        • 
          
      • Suggest the next diagnostic and draft a prediction for it
        • 
          
      • Flag conflicts and unknowns rather than resolve them by plausibility
        • 
        
      
      
      
      
      
        The application enforces
        
      Check every claim
      
        
        
          
      • Quotes must be literal spans of a source document
        • 
          
      • Numbers come only from typed, deterministic calculations
        • 
          
      • Predictions lock and hash before any outcome is revealed
        • 
          
      • Every evidence reference is validated after each response
        • 
          
      • Repairs come from an allowlist and must pass regression checks before recovery is claimed
        • 
        
      
      
      
      
      
        A person decides
        
      Approve, reject, or defer
      
        
        
          
      • Proposals are bounded in scope, reversible, and carry stop conditions
        • 
          
      • A written rationale is required for every decision
        • 
          
      • A single-case result never authorizes an organization-wide fix
        • 
          
      • Mission-to-receipt links are explicit operator actions that can be revoked
        • 
          
      • No code path executes a production change
        •
